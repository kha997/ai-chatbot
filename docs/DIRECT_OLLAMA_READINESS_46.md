## Future trial design

1. **Boundary.** One pinned Ollama Linux 0.31.1 daemon and its runners in a private WSL mount/PID/IPC/network sandbox with an empty synthetic HOME and loopback-only `127.0.0.1:11436`. No egress, Windows interop, shared Ollama 11434, inherited secrets/device FDs, host sockets or real repositories. Expose `/dev/dxg` only to the daemon and its runners and pin the minimum resolved read-only CUDA/WSL driver libraries after dependency review. The small fixed HTTP client needs only private loopback, no GPU or other tools. Require an independent examination of the exact mounts, FDs, processes, routes, device exposure and cgroup settings before requesting approval.
2. **Store.** Bind only the existing six-file `D:\ProjectData\AIChatBot\ollama-models` read-only at `/store`. Set `OLLAMA_MODELS=/store`, disable cloud and pruning, and use a private tmpfs with **256 MiB** maximum for transient state separate from the model files. The version-pinned startup normalizes legacy colon-prefixed blob names. This store has the recognized `sha256-` layout and the required directories already exist. Actual read-only startup, mmap and GPU load are unverified. A required write to the model store or a request for broader mounts must stop the attempt. [Stored model receipt](https://github.com/kha997/ai-chatbot/issues/39#issuecomment-7075781476) · [Manifest paths](https://raw.githubusercontent.com/ollama/ollama/v0.31.1/manifest/paths.go) · [Blob normalization](https://raw.githubusercontent.com/ollama/ollama/v0.31.1/server/fixblobs.go).
3. **One request.** Require a new Owner comment bound to the exact reviewed launcher, model manifest and fixture, and reserve one new permanent use record before launch. One explicit startup, then verify the private listening socket without an HTTP probe. Without OpenCode, allow the fixed client exactly one `POST /api/chat` with model `qwen3:14b`, `stream:false`, `think:false`, `keep_alive:0`, JSON format, `num_ctx:2048`, `num_predict:128`, and `temperature:0`. No retries, redirects, extra requests, tools, pull, or CPU/cloud fallback. Enforce the one-request counter, **16 KiB** request and **256 KiB** response bounds. A failed startup or incomplete response still ends the single attempt. [Ollama 0.31.1 native chat route](https://raw.githubusercontent.com/ollama/ollama/v0.31.1/server/routes.go) · [Chat request fields](https://raw.githubusercontent.com/ollama/ollama/v0.31.1/api/types.go).
4. **Acceptance.** Reuse the synthetic `combine_windows` bug and three unit tests from Issue #42. The input is the fixture function, the positive-width half-open interval rule and an example, with no answer key or real data. Require HTTP 200 and a completed response for the pinned model, no tool calls, and exactly two JSON strings `old` and `new`, rejecting duplicate keys, trailing text and unexpected edits. The expected change is `if start <= merged[-1][1]:` to `if start < merged[-1][1]:`. A trusted verifier applies only that substitution to a disposable copy and runs all three tests. It executes no model-generated code or commands. The independently checked baseline had two passes and one expected failure; the trusted edit passed all three. These fixtures were read, not rerun, in Issue #46. [Issue #42 fixture evidence](ONE_LOCAL_PROMPT_READINESS_42.md#proposed-task-and-one-run-limits).

Terminate the private process group, reap all children, verify listener and cgroup removal and clear only verified disposable scratch. Record startup/POST counts, elapsed time, RAM and VRAM peaks, unit results, released resources and one-use status.
