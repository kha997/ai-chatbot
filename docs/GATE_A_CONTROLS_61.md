# Gate A data boundary, safety and rollback design

Date: 2026-11-23. [Preparation](GATE_A_PREPARATION_61.md) · [Case oracles](GATE_A_CORPUS_61.md) · [Budget](GATE_A_BUDGET_61.md). **Proposed controls; not implemented or tested. All runtime observations NOT_RUN.**

## 1. Trust and provider data policy

Preserve [ADR-002](NHD_MVP_ARCHITECTURE_59.md) and [platform contracts](NHD_PLATFORM_CONTRACTS_59.md): trusted ingress binds tenant/channel/session/role before reading any resource; model text cannot grant authority. The selected synthetic NHD worker has no HANU/ZENA read grant or knowledge-promotion credential. Cross-tenant test setup is a separate trusted fixture custodian; never feed foreign canaries into the NHD prompt as a test shortcut. SQLite and actor strings remain local synthetic test mechanisms, not production identity. No public listener, customer browser, real login, file upload, outbound webhook or notification.

Default eligibility is **deny**. Only exact hash-approved synthetic/public text listed in the frozen manifest may cross the proposed provider boundary. Being supplied by a user, appearing on the internet, or being redacted is insufficient provenance. In this experiment, human input is a manifest case ID selected locally, not arbitrary live free text. The case loader resolves approved bytes; no runtime clipboard, filesystem scan or business document ingestion. Public documentation citations in this dossier do not authorize bulk third-party text upload.

| Field group | Future provider allowlist | Local-only / deny |
| --- | --- | --- |
| Instructions | Frozen generic system/developer text and closed response schema | AGENTS.md, private prompts, account/settings, repository paths |
| Input text | Exact approved synthetic case message; bounded same-case synthetic history | Live chats, real names/contact/address/customer IDs, unknown tenant/user content, private Word attachment |
| Scope | Opaque synthetic tenant label, locale, approved capability/intent enums | Real identity/auth/role tokens, tenant override, staff proof, customer/session handle, consent token |
| Slots | Approved synthetic product/service reference, quantity string, unit/currency enums, validated flags | Payment/address/PII, real catalog/prices, arbitrary metadata or injected keys |
| Evidence | <=5 approved NHD passages, <=3000 input tokens within total cap; synthetic document/paragraph/version/validity identifiers and approved text | HANU/ZENA sources, inactive/revoked sources, raw DB rows, oracle answers, hidden grading labels, private source hashes revealing business content |
| Protocol config | Exact model; input text; frozen instructions/schema; `max_output_tokens=1000`; `reasoning.effort=none`; `store=false`; foreground non-streaming; standard service tier | Tools, files, images/audio, metadata, previous_response_id, conversations, background jobs, web search, embeddings, model fallback, third-party tracing |

Table is a design allowlist, not an implemented API payload. Final exact wire keys and nested closed schemas must be reviewed at the later implementation gate; no wildcard or arbitrary extra JSON. Text limits: user message <=2048 UTF-8 bytes, serialized total request <=32768 bytes, full input <=8000 billed tokens including instructions/history/schema/evidence and framing; response transport <=65536 bytes and <=1000 total billed output tokens. Byte limits do not prove token limits. Bounded tokenizer/framing evidence must support the input bound; unknown overhead blocks dispatch. Never silently truncate authority/source IDs or mandatory facts to fit; return bounded local failure.

Before **each** of the at most two calls per turn: authenticate synthetic context, validate case membership/provenance/hash, reject unexpected fields/type/size, check source ACL/version/validity/tombstones and revocation epoch, build only allowlisted fields, scan for prohibited content, check byte/token bounds and reserve budget durably. Source text remains data, never higher-priority instructions. Detector mismatch or uncertain PII/secret classification → deny and STOP for review; do not send a model a question to classify privacy. Redaction is for minimized local diagnostics, not a technique to launder unknown content into provider eligibility. URL/file/attachment requests are denied locally with zero egress; no DNS/fetch of injected links.

Proposed egress: only the budget gateway holds a dedicated test credential; application worker cannot open external network or read that credential. Gateway may POST only to official `api.openai.com:443`, path `/v1/responses`, with certificate verification and redirects disabled; this is a proposed destination, **not activated**. Selected global processing has no promised country residency; actual region/terms need approval. If regional processing is required, freeze the exact documented host/region and revised price before approval, never automatic route switching. DNS resolution is restricted infrastructure traffic, not arbitrary URL access. All model tools, auxiliary inference, telemetry exports, proxy fallbacks and other destinations denied. Host admin compromise remains outside the proposed application proof and requires security review; do not claim absolute cap under stolen-key misuse.

## 2. Output and business authority

Model returns a bounded closed object: proposed behavior enum (`answer/clarify/refuse/handoff/error`), proposed intent enum, validated slot candidates, approved claim IDs, exact source/version/paragraph references, missing-slot IDs and safe non-authoritative wording. No executable action field, SQL, URL, role/tenant switch or consent decision. Reject malformed JSON, extra fields, unsupported intent, invalid types/lengths, unknown source/claim IDs and tool calls. A parse failure is not repaired by an automatic extra model call. Never forward raw provider output directly to a visitor or queue.

Application rechecks scope, state/consent/control epoch, source status and clock after completion. Deterministic renderer emits authoritative amount, currency, stock, policy conditions, source and validity only from active approved structured records/templates. Valid citation plus false accompanying claim must fail semantic validation; schema validity is not truth. Safe model wording cannot smuggle an unverified policy/amount. Money uses existing exact-Decimal single-item oracle, no new rounding/tax/shipping semantics. Missing authoritative record → honest no-knowledge/clarification, no quote. No LLM-issued quote/order/payment/consent/booking/handoff action is executed. Mock handoff is a separate explicit synthetic actor action, authorized against exact summary hash/purpose/expiry and tenant; model can only suggest an offer.

State layers: bounded session context only; no customer-memory learning or cross-session preference store. Approved organization knowledge is immutable during a scored run. Proposed corrections are quarantined local review records, not promotions; runtime has no write grant. A later promotion needs different approver, exact diff/current-version match, regression and rollback review. For this run, any attempted promotion is denied and tested; no policy update is allowed merely because a claim repeats.

Missing source in an ordinary declared no-knowledge case is expected and yields abstention. Missing a **required frozen fixture/authority source** is a STOP condition, not an opportunity to reinterpret the oracle. Revocation during generation suppresses stale output. Consent withdrawal or mock human takeover cancels unsent work, suppresses late output, and cannot retract bytes already accepted by the provider.

## 3. Required pre-execution control evidence (all NOT_RUN)

| Control proof | Required future offline evidence / release gate |
| --- | --- |
| Allowlist / provenance | Captured fake transport for both extraction and reply; unexpected nested fields/unknown hash/PII-like text produce zero outbound requests |
| Tenant/source | Access traces proving no foreign fetch, cache, queue, export or citation; revocation wins before fetch and before output |
| Model containment | Forged amounts/policies with valid citations never rendered; no role/action/consent mutation |
| Consent/human | Atomic withdrawal, summary change, takeover/late output and ordered return tests; no premature receipt claims |
| Budget | Durable reservation, concurrency boundary, retry/error/crash matrix from budget document; gateway cannot be bypassed |
| Oracle integrity | Exact source/case/schema/prompt hashes; independent semantic-family review and disjoint development split |
| Host/network | Isolated local setup, no public listener/persistent service; worker network denial, dedicated gateway-only credential custody and fixed host/path; no other project access |
| Rollback | Mock kill switch plus restart default-closed, tombstone/restore and ambiguous-call reconciliation; retained failure receipts |

This PR specifies these proofs only. No “safe to execute” verdict until implementation and independent offline qualification are separately authorized and passed. All T1–T13 rows in the corpus plan are mandatory within the narrow synthetic boundary. Real identity/MFA, real channel signatures/delivery, backup/purge operations and production encryption are not demonstrated by mocks and remain later gates.

## 4. Stop, reconcile and retain

Any operator/reviewer may request STOP; lead owns containment, separate security reviewer owns clearance. Kill switch first atomically marks run STOPPED and forbids new dispatch/retry; revoke admission leases, terminate unsent queued work and suppress output. Revoke future test key in the approved account if issued; disable gateway outbound capability using the later approved procedure. No account or firewall change is performed now. Keep outstanding reservations: timeout/cancel/revocation does not prove provider cancellation or nonbilling. At most five already-admitted calls remain inside the prepaid worst-case reservation; no further inference to investigate an error.

Persist minimal run/case/attempt IDs, hashes, source/config revisions, state transitions, sanitized error category, timestamps, usage and cost reservations/receipts. Never log Authorization headers, raw secrets, PII, account identifiers or raw HTTP bodies to GitHub. Only approved synthetic response fragments and aggregate receipts may be public after review; request IDs/account references can be restricted or hashed if correlation would expose access details. Proposed local synthetic content retention 7 days and audit 30 days, subject to later approval; no new backups/services. Final public sanitized research receipts persist with repo history. Provider retention is independent; `store=false` is not zero-retention assurance ([official data controls](https://developers.openai.com/api/docs/guides/your-data)).

On restart, default STOPPED. Verify original manifest, ledger continuity and exclusive run lock; outstanding/ambiguous reservations remain fully charged. Reconcile via approved non-inference billing evidence, never resend to learn whether a request happened. Preserve original failures and unknown usage. An unknown charge, broken ledger or pricing mismatch cannot be cleared by a new run ID. After a hard violation, new manifest/independent review and explicit Owner reauthorization are required before any more experiment calls. Roll back to deterministic mock/no provider egress; apply latest tombstones before restoring source/context snapshots. No rollback changes another project or activates a fallback provider.
