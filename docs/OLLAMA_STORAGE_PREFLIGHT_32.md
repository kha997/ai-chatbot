## Read-only alternative and decision

A file-level Bubblewrap read-only bind of exactly the six source files would avoid the copy and block writes from that Linux sandbox. It does not stop the shared Windows service from changing or pruning those files, nor does it create a stable project-owned snapshot. Ollama 0.31.1 invokes blob repair at startup before its optional prune guard. `OLLAMA_NOPRUNE` alone cannot certify a read-only store. No real source model file was mounted in a sandbox or attached to a process. The protected independent D: store is preferable if the remaining runtime checks pass. [Ollama startup source](https://raw.githubusercontent.com/ollama/ollama/v0.31.1/server/routes.go).

The lowest-cost next action is an explicitly scoped adapter-only validation against a fake loopback HTTP peer, with cloud and model endpoints unreachable. It must observe the installed compatible SDK making and validating exactly the expected mock exchange. Establish a separately approved empty-store compatibility test with no model bytes and no GPU device exposure. Ollama 0.31.1 performs device discovery during startup. Keep the real copy blocked until those checks clear. A later inference gate would still require host RAM **at least 6 GiB**, free VRAM **at least 12 GiB** and an Owner-coordinated exclusive GPU window. The last RAM snapshot was **5.23 GiB** with **14,022 MiB** reported free VRAM and no reservation. CPU/memory/PID/swap controls remain to be verified for a real run and cannot reserve NVIDIA VRAM. A 2,048-token context is a smoke-test budget.
