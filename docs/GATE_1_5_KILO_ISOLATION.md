## Kilo runtime and boundary

The [vendor CLI guide](https://kilo.ai/docs/code-with-ai/platforms/cli) supports extracting and invoking its baseline build. The [v7.8.32 release](https://github.com/Kilo-Org/kilocode/releases/tag/v7.8.32) lists `kilo-linux-x64-baseline.tar.gz` with SHA-256 `ab7a008a2c0ca6e035b96cd1dc5712a8466a14a45992291a8f0b4b549b94136e`. The qualification runner checked the exact input bytes, copied only the regular ELF member `kilo` into a private WSL temporary directory and did not use the archive's Bubblewrap member. It ran under Ubuntu 24.04 x64, ordinary UID 1000, using `/usr/bin/bwrap` 0.9.0. No package install, PATH or shared runtime change was required.

| Approach | Assessment |
| --- | --- |
| Linux ELF plus Bubblewrap and fixed relay | Selected. Proven loopback-only net namespace and read-only Linux runtime/work mounts. Excludes host workspace, home and Windows mounts, and ambient credentials. Allows exactly one gated provider request. |
| Windows Kilo through WSL interop | Excluded. WSL can hand Windows executables to host execution. Linux namespace checks cannot establish Windows process restrictions. [WSL interop](https://github.com/microsoft/WSL/blob/master/doc/docs/technical-documentation/interop.md). |
| Native Windows disposable isolation | Design alternative. Requires independent isolation and request-budget checks. Native sandbox not qualified on this host. |

The Linux child has a distinct network namespace with only loopback. The runner checks that host home, Windows mount and interop paths are absent and that a caller cannot write in the work mount. It passes an empty credential environment and closes inherited stdin. Linux seccomp denies non-UNIX/INET socket families, including VSOCK and packet sockets, and blocks io_uring setup. Reflection and mock tests inspect only synthetic metadata. Kilo's local HTTP endpoint can reach one Unix socket in the private exchange. The host relay reconstructs the message from the fixed synthetic text, drops every incoming credential and context addendum, requires the exact free model and uses one atomic permit. Only the hard-coded HTTPS Kilo endpoint can receive the request. There is no redirect handling, configurable upstream or paid fallback. The request permits 128 output tokens, with a 32 KiB response cap, 128 KiB per child stream and a 45-second outer child deadline. The live invocation also reserves a durable exclusive marker in the launching WSL user's passwd home.

The installed Bubblewrap is affected by the pre-start mount setup issue in [CVE-2026-87766](https://ubuntu.com/security/CVE-2026-87766). For this bounded run the mount destinations were fixed, the temporary directory had trusted parents and private permissions, and untrusted archive paths were never used as mount destinations. Only vetted system runtime paths were bound, and independent inspection found no pathname sockets there. Child code starts after mount setup. This mitigation is narrow and does not qualify this Bubblewrap version as a reusable boundary for arbitrary jobs.
