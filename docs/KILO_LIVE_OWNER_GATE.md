## What changed since the prior live failure

The historical relay hid upstream media mismatches behind SSE 200, scanned JSON line by line before framing, and could overrun its own Unix envelope. The original live cause remains **UNKNOWN**. PR #17 corrected those three defects. This packet exercises their fixes with the patched namespace, a frozen request plan and a synthetic HTTP response reader that verifies status, encoding, header conflicts and declared body length before the SSE validator. Accepted SSE is forwarded byte-for-byte through the bounded frame. Observations are safe categories and counts, with allowlisted token counts when present and unknown otherwise. No prompts, sessions, raw upstream bodies or generated output are published from runtime.

The runner only accepts concrete offline fixture data. There is no provider connection constructor, externally injected callable, token minting path or live executable mode. The module entry point exits `NO_LIVE_AUTHORIZATION`, and the runner rejects a `live` argument before touching its archive. The request contract fixes HTTPS verification, zero redirects/retries, anonymous headers, request body and model. The synthetic reader and permit prove offline behavior, but do not exercise an actual TLS socket or live billing. The anonymous public model catalog GET confirmed exact-model prompt/completion prices `0` on the observation date. It did not make an inference request. [Kilo anonymous authentication](https://kilo.ai/docs/gateway/authentication) · [Free-model billing](https://kilo.ai/docs/gateway/usage-and-billing).

An approved activation will need a separate, independently reviewed executable artifact on an exact SHA with a durable one-use authorization record. The decision here covers review of the pinned technical candidate and the following one-attempt scope. It does not authorize running the offline SHA or any subsequent SHA as live.

## Proposed Owner decision and abort rules

Approve **at most one additional Kilo Free synthetic task** under Issue #8, with a single POST and **0 VND incremental purchase**, only when the exact activated runner, its same-digest sandbox/CLI, and the immutable request above are recorded and reviewed. Bind the Owner authorization to that exact activation SHA and a unique one-use run token before enabling any live route. The authorization must come from the Owner via GitHub, not a CLI label or Watcher status. No token has been created here.

The activation artifact must reserve the approved slot atomically in a private durable location before inference networking and leave the reservation consumed even after a timeout, rejection or process crash. Require the reviewed commit and file digests, the exact patched sandbox binary, a fresh public exact-model zero-price check, ordinary WSL UID, no credentials or proxy, only the fixed vendor endpoint, verified TLS, hard overall deadline, one POST, no redirects/retries, and no paid or alternate model. Confirm how the gateway identifies the selected model in its response before activation. If it promises a stable ID, require that ID. The current offline SSE parser does not attest the returned model. Abort on any mismatch, missing/used authorization, nonzero or unknown price, wrong model, isolation failure or unexpected extra tool request. One sandbox-local title/duplicate refusal must never consume another external request. HTTP failure or limit, malformed framing, partial stream, failed cleanup, output cap or invalid oracle stops the attempt. No retry if the vendor returns 429.

**Success:** validate SSE media, bounded complete frames and `finish_reason=stop`. A present `[DONE]` must be valid and terminal. Its absence is accepted only at clean end-of-body with a framed stop, as demonstrated offline. Require Kilo exit 0, no JSONL error, exact three-integer oracle, one recorded POST, successful timeout/control tests, zero unintended access/writes, denied local duplicate and no remaining child processes. Record usage counts and cost receipt when supplied. Missing usage is unknown. HTTP 200 does not establish billed cost or task completion.

Before activation, rollback is simply leaving the runner inert. If an activation artifact is prepared and then withdrawn, disable and archive its private token/artifact, retain the attempt record, and return to this offline PR. After an attempted request, never delete or reset the reservation as part of rollback. The project-local Bubblewrap artifact is independent of existing paths and shared packages. It can be archived by its exact private path after no process is using it.
